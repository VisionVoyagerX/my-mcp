05 · under the hood

How this MCP works

One shared client library, two thin Cloudflare Workers, no local install.

Request lifecycle

  1. Fresh server per request. Each worker builds a new McpServer and registers its tools on every call — nothing is kept in memory between requests (stateless).
  2. Rate limiting. Every request is checked against a per-IP Cloudflare Rate Limit first. ΓΕΜΗ calls get a second, global limiter on top, because ΚΥ ΓΕΜΗ caps the one shared server key at 8 requests/minute for everyone combined, not per visitor.
  3. The shared fetch layer (packages/core/http.ts) adds a 15s timeout to every upstream call, retries 429/502/503/504 with backoff, and turns any failure into one consistent, readable error.
  4. Split by domain, not by user. citizen-mcp and business-mcp are grouped by what the data is about (transparency vs. business/tax), so installing one never pulls in tools you don't need. Diavgeia is shared by both, since procurement data matters to each domain.
